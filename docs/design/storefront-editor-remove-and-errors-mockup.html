Storefront editor · Content card

Taking things back out, and errors that point at their own field

Three small corrections to the editor a shopkeeper already uses. Nothing here adds a feature — each one closes a door the editor left one-way.

Everything below is the Content card in src/app/(admin)/storefront.tsx, at phone width. Only the affected fields are drawn; the address, headline, about and highlights sit above and are unchanged.

Three separate props — tradingSinceError, highlightsError, instagramError — each rendered under the field that owns it.

The wrong tone gains its action. Caveat’s own rule is that wrong always ships something that removes it. The shared caveat couldn’t offer one, because it didn’t know which of three saves had failed. Split apart, each can: Try again re-runs that field’s own flush.

What this does not touch

  • The walkthrough. The editor still has no guided path, and opening hours and the shop’s phone number are still edited on a different screen entirely (Settings → Locations) with nothing here saying so. Its own spec.
  • Currency. Prices stay hardcoded to $. Its own spec.
  • The Visit tab’s name. One word, still yours to pick.
  • The save model. Four separate caveats still explain that some fields save live and others wait for publish. Real, and not a Remove button’s job to fix.
