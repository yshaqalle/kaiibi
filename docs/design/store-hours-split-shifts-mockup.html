Split opening hours

A store that opens in the morning, shuts for lunch or prayer, and reopens in the afternoon — any number of blocks a day, set by the owner. The week stays seven readable rows; the day you are editing opens in place.

What already works

This is a UI change and nothing else. The column, the type and every reader were built for a list of blocks from day one — the editor is the only thing that caps it at one.

Storage — no migration

shop_locations.opening_hours is {"mon":[{"open":"09:00","close":"13:00"},{"open":"17:00","close":"21:00"}]} today. The migration comment says so out loud: “Each day is a LIST so a lunch or prayer closure can be added later as a UI change alone.” There is deliberately no CHECK constraint to rewrite.

Open/closed, receipts, formatting

isOpenAt already tests every block. formatDayHours already joins them, so a receipt prints “Open today 09:00 – 13:00, 17:00 – 21:00” with no change at all.

Shift validation

isRangeWithinHours requires a single block to contain the shift, so a 12:00–18:00 shift across the lunch closure warns — and that warning is right. It is non-blocking, so a manager who means it can still save. Already unit-tested.

New rules the editor must carry

Blocks on one day must not overlap each other, must be kept in time order, and two blocks that touch (13:00–17:00 & 17:00–21:00) are really one block. None of that exists yet — it belongs in store-hours.ts where Jest can reach it, not in the component.

The design

Seven fixed rows, each reading as the sentence it will print on the receipt. Tapping a row opens its block editor inline, underneath. However complicated the week gets, the list never gets longer than seven rows plus the one day you are working on.

Three calls this direction forces

Inline accordion, never a modal on a modal

The editor expands inside the row. A second React Native Modal stacked on the Edit store modal misbehaves on iOS and would bury Save. It also means the whole row is the tap target rather than a small “Edit” link — one tap to open, edit in place, tap the next day.

One day open at a time

Opening Tuesday collapses Monday. Keeps the list short, and keeps “Copy to every day” unambiguous about which day is being copied.

“Not set” opens with a block already in it

Tapping an unset day opens the editor showing one 09:00 – 18:00 block, rather than silently writing hours you then have to open the day to see. The default is visible and editable before it counts — and nothing is stored until Save.

Rules and edge cases

All of these belong in src/lib/store-hours.ts next to isValidRange, where Jest can reach them — the editor stays a thin consumer, as its header comment insists.

CaseBehaviour
Overlapping blocksBlocked, with the inline message shown above. Two blocks claiming the same minute make “is the shop open” ambiguous and would double-count in any future hours total.
Touching blocks
13:00–17:00 & 17:00–21:00		Merged on save into one 13:00–21:00 block. There is no closure between them, so storing two is a lie the receipt would print.
OrderSorted by start time on save. Blocks are shown in stored order, so one typed out of sequence jumps into place once — better than refusing it.
Zero-length or backwardsUnchanged: isValidRange already requires close > open, and the field goes red.
Overnight (22:00 – 02:00)Still out of scope, unchanged. A late bar splits as 22:00–23:59 today and 00:00–02:00 tomorrow, which the current type already forces.
Last block removedDay becomes [] — “Closed”. Distinct from absent (“Not set”), which is the distinction isConfigured and the scheduler depend on.
How many blocksNo hard cap. Nothing downstream cares, and a cap is a rule someone would have to justify. The Saturday row above shows three.
Copy to every dayCopies the open day's blocks over all seven, including days currently “Not set”. Most shops keep one pattern all week — set it once, then fix the days that differ.
A shift across the closureWarns “outside opening hours”, non-blocking — the existing behaviour and the correct one. A 12:00–18:00 shift at a shop shut 13:00–17:00 is worth a second look, not a refusal.
Receipt“Open today 09:00 – 13:00, 17:00 – 21:00”. Already exactly what formatDayHours produces.
