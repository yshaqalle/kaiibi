What actually changes

One element moves between two JSX parents in the same file. No new component, no styling change to the switcher itself.

WhereChange
admin-sidebar.tsx · header Remove <LocationSwitcher /> from styles.headerText. That column drops back to name + subtitle, and its gap: 4 / alignItems: 'flex-start' comment stops applying — worth updating.
admin-sidebar.tsx · topBar Render <LocationSwitcher /> before the ☰ Pressable. topBar already has justifyContent: 'flex-end'; add gap: 14 to match the mobile header's spacing.
location-switcher.tsx Untouched. Light tone is already correct against the white top bar.

Single-location shops see nothing

The switcher returns null unless the shop has 2+ locations, so for most shops the top bar keeps just the ☰ and the sidebar header loses nothing. The move is invisible to them.

This also changes tablet

AdminSidebar is shared: desktop web renders it above 900px, and native iPad/Android tablets render it too. Editing it moves the switcher on tablet as well. That lands all four shells on the same placement, but it is not a web-only edit — say the word if tablet should keep the sidebar position.

Vertical rhythm

The sidebar header is currently 34px avatar against a three-line text column, so the avatar floats. Removing the third line leaves two lines against the avatar — closer to balanced, and the same shape the mobile header already has.
