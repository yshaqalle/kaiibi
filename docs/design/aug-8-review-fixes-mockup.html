1 · The "All stores" rota template rejects its own rows

With All stores selected, the downloaded template stamps every row with the primary store's name — including rows for staff assigned only to another store. The manager fills in times, uploads the same file back, and the importer refuses the rows the app itself wrote. schedule-tab.tsx:196 computes the store once; parseScheduleRows then enforces per-member assignment on re-upload.

2 · "Take photo" on a till that has no camera

The shared contract comment (camera-photo-button-shared.ts) promises the button "renders nothing" on a camera-less device, and three call sites lay out their photo rows trusting that. The web build honors it; the native build never checks — the button renders as the primary action and every press ends in an error. One of the two halves has to move.

The strongest visual weight on the row belongs to an action this device can never complete.

Proposed — option AThe button owns its existenceproduct-form · camera-less till

Native asks the OS whether a camera exists (as web already does) and renders nothing without one. "Choose photo" sits alone at full width — the layout the call-site comments already describe.

Option B — keep the behavior, fix the words

Visually identical to "Current". Native keeps its deliberate show-and-explain press (per photo-picker.ts), and the shared contract plus the three call-site comments are rewritten to say so. Zero UI risk, but the dead-end primary button on the till stays. A is the better product; B is the smaller change.

3 · The keypad caret draws under the text, not after it

New in d2f1323: the keypad-driven search field draws its own caret, since a Pressable has no system caret. But the caret View is a column sibling of the text inside a default-column Pressable — nothing lays them out in a row — so it lands at the bottom-left of the field, under the text. Needs a simulator screenshot to confirm; this is read from the styles.
