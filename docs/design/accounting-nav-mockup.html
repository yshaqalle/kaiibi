Knowing where you are in Accounting

Nine tabs, two of which open hubs, and those hubs open eighteen more screens. The header that is supposed to place you in that tree currently spends three of its four lines saying nothing useful — and puts the one line that does say something below the title it qualifies.

The ordering is the real defect. You read the leaf — General Journal Entry — before you are shown the branch it hangs off, because the tab row renders under the title block. Every other hierarchy in the app, and every breadcrumb anywhere, goes the other way: where you are, then what it is.

The second failure is that the eyebrow is a constant. <Text style={styles.eyebrow}>ACCOUNTING</Text> is literal in the shell, so the line that occupies the most prominent "where am I" slot is the one line guaranteed never to answer it. On the Bills tab it says ACCOUNTING. On Payroll it says ACCOUNTING. Inside a stock report three levels down, it still says ACCOUNTING.

Strictly the most correct hierarchy — nav, then place, then thing — and the crumb gets shorter because the tab row above it already carries the first level. The cost is real though: the tab row is nine pills that scroll horizontally on a phone, so putting it first means the first thing on every Accounting screen is a scrollbar rather than a heading. I would not ship this on mobile.

3 · The naming problem underneath

No breadcrumb design fixes a crumb that reads Accounting › Accounting › Trial Balance. The tab named "Accounting" inside the module named "Accounting" has to be renamed, or option B produces this:

Accounting›Accounting›Trial Balance  ← what the crumb says if nothing is renamed

Accounting›The books›Trial Balance  ← with the tab renamed

The tab's own blurb already calls it "The books themselves — accounts, entries and the trail behind them." So The books is not a new coinage, it is the words the tab already uses about itself, and it distinguishes the ledger from the module in one syllable more than "Ledger" does while staying in the plain-speech register the rest of the app uses (Owed to you, not Receivables).

CandidateCrumb reads
The booksAccounting › The books › Trial BalanceRecommended — the tab's own blurb, and matches "Owed to you" in register
LedgerAccounting › Ledger › Trial BalancePrecise, and the term the code uses throughout (LEDGER_VIEWS, ledger.view). Bookkeeper's word, not a shopkeeper's
JournalsAccounting › Journals › Trial BalanceNo — Journals is already one of the screens inside it
leave as AccountingAccounting › Accounting › Trial BalanceNo — this is the bug, written down

Renaming the tab label does not touch the route, the ?tab=accounting parameter, the AccountingTab type or any permission — it is the label field on one entry in TAB_OPTIONS. Deep links people have already shared keep working.

4 · The crumb on a phone

Three levels will not fit on 380px. It truncates from the left, which is the end that matters least — you know you are in Accounting because you tapped Accounting.

The module level becomes a bare ← rather than being dropped, so the tap target survives even when the word does not. This is the same rule the hub cards now follow after the export work: shrink the chrome, never the label that carries meaning.

5 · What I would build

  • Option B. One <Breadcrumb> row replacing the constant eyebrow and LedgerCrumb. Ancestors are links, the leaf is plain, and the trail is derived from tab + view — the two pieces of state the shell already holds, so there is no new source of truth to keep in sync.
  • Rename the tab label to "The books". A one-field change with no route or permission impact, and without it the crumb repeats itself. This is the part worth agreeing before I start.
  • Leave the tab row where it is. Option C is the better hierarchy on a desktop and the worse one on a phone, and this app is read on phones.
  • Not in this pass: the same constant-eyebrow pattern is on Inventory, People and POS. Worth a sweep once the component exists, but it is only load-bearing here, because Accounting is the only module that goes three levels deep.
