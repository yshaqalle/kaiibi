Kaiibi · storefront · design note

The address should look like the shop, and the page should be able to carry a flyer

Two gaps left open after the storefront series shipped. Neither is a new subsystem — both sit on the editor and the three themes that already exist. This is what they should look like before anything is planned.

Part one — the address follows the shop's name

Today the editor suggests a slug and then leaves the shop with a blank box when it is taken.

Two shops called Xamdi Electronics end up at unrelated addresses, and the one that loses the race has to invent a name rather than adjust the one it already has. A customer who knows the shop cannot guess the link — which is the entire job of a custom address.

Derived, not suggested

The address starts as the shop's name and stays in step with it — until the moment it is claimed.

A suffix, not a blank slate

On collision the base is kept and frozen. The shop appends; it does not start again.

The suffix is a place, not a number

Prefilled from the primary location's neighbourhood. -2 reads like a mistake; -koodbuur reads like an address.

A claimed address never follows a rename

Renaming the shop must not move its web address. Links are printed on cards.

Part two — flyers

A shop wants to put the seasonal poster and "everything 20% off this week" on its page.

Today the page has one optional hero image that only the Window theme reads, and nothing that can carry a promotion. The editor already has the content drawer and the draft column, so flyers are draftable for free — a shop can prepare next week's poster without publishing it.

One upload path

The same uploadImage() logos, product photos and the hero already use. Not a fourth.

None renders nothing

No empty frame, no placeholder. The photo-optional rule every theme already follows.

One is a hero

A single flyer renders static, with no dots and no arrows. A carousel of one is a lie.

Counter gets none

It is a dense price list built to make a 200-line catalogue readable. A carousel fights that.

Motion

A carousel that moves while somebody is reading is worse than a static image, and this page is read on a phone over a slow connection in a shop doorway.

  • Auto-advance is off unless the shop turns it on. The default page does not move by itself.
  • It never moves under prefers-reduced-motion, regardless of that setting — the customer's preference wins over the shop's.
  • It stops on hover, on touch and on keyboard focus, and does not resume for that visit.
  • Dots and arrows always work, whether or not it auto-advances. Swipe too.
  • Each slide is a real link or button, so a screen reader and a keyboard reach it in order.

What this costs in schema

ObjectWhy
storefront_flyers One row per slide: storefront_id, image_path, headline, subline, link_kind, link_value, position, draft. Read publicly through the existing security definer pattern, never by direct table grant.
A public read Extends the storefront read RPC rather than adding a fourth: an unpublished shop and an unknown slug must stay byte-identical, which is only true if flyers travel with the same call.
auto_advance One boolean on storefronts. Off by default.
No new bucket. product-images is already public, which is what a customer-readable flyer needs.

Deliberately not here

Left outWhy
Scheduling a flyer to appear on a date Worth wanting and much bigger. Draft plus a tap is enough to run a week's promotion today.
Tying a flyer to the promotions module A flyer is marketing; a promotion is pricing. Conflating them makes the discount engine's behaviour unclear, and the discount engine posts to the ledger.
Reserving an address before it is claimed Stays first-come. claim_shop_slug already raises slug_taken on a lost race.
Redirecting an old address to a new one Needs a history table and a resolver that fails open — the opposite of how slugFromHostname is built. Separate change.
Video flyers Autoplaying video on a metered connection in Hargeisa is a cost the shop's customer pays.
