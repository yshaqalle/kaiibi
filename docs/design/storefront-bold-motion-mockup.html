The composition, top to bottom

  • Photo hero with a real bottom-weighted scrim, the serif wordmark rising in once, the open pill living on it. No photo → the aurora anchor from §1 takes its place. RN: Image + LinearGradient + Reanimated entering
  • Floating search overlapping the hero's edge — the platform-shot move that makes the page read as designed, not stacked.
  • The carousel is the shop's flyers — flyer-carousel.tsx already ships in the codebase; this finally gives it the promo-banner slot the references all have. Touch swipes; a mouse gets every affordance too — wheel pans it, drag grabs it, the dots are clickable, and arrows appear on hover. The production build needs the same wiring: RN-web horizontal lists don't speak mouse by default, so wheel/drag/arrow handlers go into the carousel task explicitly. RN: exists + web mouse handlers
  • Photo categories, tag-on-photo cards, NEW badges — the §4 vocabulary in its final position.
  • The slip rides sticky over the scroll, exactly as specced in the parked plan — fly-to-cart works here too, into the sticky slip.
  • The ink footer closes it with the colophon — the page's one dark bookend, since the hero carries a photo instead of ink.

The references, honestly

Dribbble renders nothing to a fetcher, so the five shots (27193963 skincare · 25717053 platform · 24925028 Getdecor · 25472436 fashion app · 14359250 design-shop site) were read as their genres. What they agree on is this page's spine: serif editorial hero, floating search, promo strip, visual categories, price-forward cards. What was refused: wishlists, ratings, variant swatches — chrome for data models kaiibi doesn't have.

The composition

  • Kaiibi masthead, kaiibi blue — wordmark, one-line promise, and a search that finds things as well as shops: the directory rows already say what each shop sells, so "shirts" finds every shop selling shirts. That is the directory's killer feature, and today it is invisible.
  • City chips — the first real filter a customer has.
  • The featured shop as a hero — featuredShop() already picks one; give it the photo-scrim-serif treatment and a blue Visit button. This is also the merchant-side prize: being featured looks like something.
  • Shop cards with life — photo, an open dot with the word (never colour alone), the city, and what they sell as quiet tags. Closed shops say when they reopen instead of just being grey.
  • Hover lift + stagger-in — the same tier-1 motion grammar as the shop page. RN: Reanimated entering + web hover

One rule carried over: each shop's card stays neutral — the shop's own palette blooms on their page, not in the list. The directory is kaiibi's room; the shops are its guests.

The shop's own cover photo, blurred to an ambient backdrop, with frosted cards floating over it. Depth instead of flatness — the closest thing to "wow" a storefront can wear while staying legible. Falls back to solid ground cards wherever blur is unavailable or the shop has no photo.

What ports

  • Photo category tiles — the single strongest steal from the tag: categories as image cards with a scrim and a count, not text pills. The photo is derived — each category borrows its first product-with-photo — so no new merchant work, and a photoless category degrades to today's pill. RN: Image + gradient scrim, exists
  • The price tag on the photo — a ground pill sitting on the image, where the tag's shots put it. The price is the number the customer came for; on the photo it reads first, and the text block under the tile gets simpler.
  • The NEW badge, from data we have — products carry a created-at; anything ≤14 days wears an accent chip. Zero backend, and it gives regulars a reason to re-open the link — "what's new since last week" is the storefront's only recurring story.

What doesn't, and why

  • Colour-blocked pastel tiles (every product on its own tinted plate) — the tag's signature look, and a direct fight with this system's doctrine that colour is rationed and palette-derived. A six-palette shop wearing rainbow plates stops being its palette.
  • Swatch dots, ratings, wishlist hearts — each assumes a data model (variants, reviews, accounts) kaiibi's products don't have. Designing the chrome before the model is how a page fills with dead controls.
  • Floating cart bubble — redundant with the slip, which already carries count, total and evidence.

Why this is buildable and the React Bits imports are not: everything above is transforms, opacity, gradients and blur — the four things Reanimated + Skia + expo-blur do natively at 60fps, on the same code path the web page uses. Nothing here imports a DOM library, loads WebGL, or adds a dependency the app doesn't already carry. The React Bits catalogue supplied the vocabulary — aurora, split-text, count-up, spotlight — and this is that vocabulary spoken in the storefront's own language: palette-derived colour, once-only motion, reduced-motion no-ops, and the slowest phone in Hargeisa still first in line.
