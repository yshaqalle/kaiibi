Finishing the plan lifecycle: create, publish, archive

Retirement shipped. What's left is the two ends of a tier's life: bringing a new one into the world without it going live half-built, and putting a fully-drained one away without deleting it. Every frame is pinned to Colors.light, the palette the app actually renders.

Create — server ready, no door

upsert_plan already creates on an unknown key. But PlanEditor is only reachable from an existing card's Edit button, and a plan created through it would be born with is_public = true — live in every store's plan picker before its modules are even ticked.

Archive — no path at all

active = false is the schema's designed end state ("the portal deactivates plans instead of deleting them") but active is deliberately outside upsert_plan's allowlist and nothing else writes it. And since every plan query filters active = true, an archived plan would vanish from the portal itself — a one-way door unless the portal learns to list them.

Delete — never, and that stays

shop_subscriptions.plan_id is on delete restrict on purpose. Nothing below adds a delete. Archive is the terminal state; the row, its audit trail and its revenue history stay.

3 · Publishing a hidden plan

A hidden plan's card gains a Publish button next to Edit. One confirm, one line about what it does. This is a new publish_plan action, not a relaxed republish_plan — republish's retire_at guard is the only thing standing between a benign-looking call and making trial ($0, every module, no limits) publicly pickable. Publish gets the same tripwire: it refuses the trial key by name.

4 · Archive — the end of the line, and the way back

Archive appears on a card only when the server would accept it (the same rule Retire already follows): the plan is off the picker, no subscription rows point at it, nothing else depends on it. Archived plans drop out of the grid into a collapsed strip below it — visible, restorable, out of the way.

Open decisions

Does Archive require Retired first?

The sheet above only requires drained (0 subscriptions), which also covers a hidden plan that never launched. Requiring a full retirement first would be stricter but makes killing an unlaunched draft absurd — retire it to whom? Proposed rule: 0 subscriptions + not public is enough.

Billing interval and currency in the create sheet?

The editor today never touches them; every plan is monthly USD. The create sheet above inherits that and leaves both to their column defaults. Adding the fields is trivial later; adding them now is two more ways to misconfigure a plan nobody has asked to vary yet.
