Count · by hand

One list, one step

Counting a shelf today takes three gestures per product: find it in the catalogue, press Count to move it into a basket, then type the number into the basket copy. The catalogue and the basket are the same products twice. This drops the middle step — every product is already a line, and typing a number is counting it.

1 · Find the productSearch, category, or page through. Unchanged.
2 · Press Count to add itGone. The row is already there.
3 · Type what you foundNow the only action.

Save counts
Blank is a real state, and it is the default An empty field means “I did not count this” and the product is left exactly as it was. Only rows with a number are sent.
Zero still means an empty shelf Typing 0 is a claim — the shelf is bare — and it commits. This is why blank and zero must look different, and why an untouched field renders — rather than 0.
× clears one line Appears only on a counted row. It returns that row to blank — it does not delete the product, because the product was never added in the first place.
Clear all starts the walk over Beside Close, where a destructive action belongs. It empties every field on every page, the reasons and the note, and leaves the store and the tab where they are.
Paging

A hundred at a time, and invisible below that

Most shops on the platform carry fewer than a hundred products, so for most of them the pager never appears at all — one page, no controls, nothing new to learn. It shows up only when the catalogue is genuinely long.

100 per page Below that threshold the whole pager row is absent, not greyed. A control that can never do anything should not be on screen.
Search and category page too Filtering narrows the set first, then paginates what is left — and resets to page 1, because staying on page 3 of a set that now has 12 rows shows nothing.
Typed counts outlive the page Go to page 2, come back, and page 1’s numbers are still there. The counts belong to the walk, not to what happens to be rendered. Same for changing the search or the category.
Save covers every page The footer and Save count everything typed, not what is visible. “4 counted so far, on any page” in the pager says so out loud, because this is the one thing a person could reasonably get wrong.

That third point is the one to be careful about in the build: it is exactly the shape of bug that has bitten this feature before — state tied to what is rendered rather than to the work. A count typed on page 1 and silently dropped by paging to page 2 would be invisible until a shelf came out wrong.

Confirm

Save asks first, and shows its working

Count sets a number. There is no undo, and a mistyped row overwrites a real shelf. So pressing Save counts does not write — it unfolds this, in place, where the footer was.

It unfolds, it does not pop A modal presented from a modal is silently dropped on iOS — the button just reads as dead. This panel replaces the footer inside the sheet already on screen, the same way the reason chips do.
The headline is the number that matters “3 products will change” — not 4, the number counted. A row counted at the figure it already held changes nothing, and saying otherwise overstates what you are about to do.
Every change, from and to The whole point of a confirmation is auditing it. Names, both numbers, and the reason each carries — including no reason given, because unexplained shrinkage is the finding.
The store is named Stock‑takes go wrong by being saved against the wrong branch. The one screen that can catch it is the one right before the write.
The expense is disclosed here too If the stock‑loss box is ticked, this write also touches the P&L. That belongs in the confirmation, not only in a checkbox scrolled past.
Go back, not Cancel It returns to the list with everything intact. “Cancel” reads like it might throw the walk away, and on a shelf you just spent twenty minutes counting that ambiguity is cruel.

One edge worth naming: if nothing would change — every counted row already matched — the confirmation says so plainly and still offers to save, because recording that a shelf was checked and found correct is a real and useful result.

What this changes beyond layout

The two‑step version had a rule: every line in the basket must read a number before Save is allowed, because a line only existed if you put it there. That rule cannot survive here — every product is a line now, and almost all of them will be blank.

The footer gains one figure — 236 left alone — because with the whole catalogue in play, “how much of the shop did I actually walk?” becomes a question worth answering, and it is the honest reading of a partial stock‑take.

One thing worth your call

Typing into the wrong row is easier now, with no explicit “add” to confirm intent. Three things mitigate it: a counted row is tinted, it carries a ×, and nothing is written until the confirmation names every product by name with both numbers beside it.

If that still feels thin for a door that overwrites stock, the next lever is making the confirmation scroll rather than truncate for large counts — so “40 products will change” is a list you can actually read, not a number you have to trust.
