Four things the real data showed

The feature works — owner names, cities, branch chips and the team row are all on screen against eleven real stores. What the mockup could not predict is what real rows look like: most stores have no phone at all, some have an email where a name should be, and two labels read like bugs.

The rule is the one the design already wrote down for the Overview and never applied here: owner’s phone → store’s phone → email. Only a store with neither shows “no contact”, and that should be rare, because every owner row has an email by construction.

Green stays rare. Nine identical green circles would have said nothing; nine grey ones say something true.

What is deliberately not changing

“Their team — Abid, Ali, Jaalala” listing a second Jaalala. The summary excludes the owner, so that is a different member who happens to share the name — real data, correctly rendered. Hiding it would be worse.

No branch chip on single-branch stores. Ten of eleven stores have one branch, so the chip is almost never drawn. That is the rule working: “All branches” beside a store with one branch is noise. It appears on Jaalala Skincare, which has two — and it did.

yusefshop’s number, 3253253253. It has no country code and is almost certainly junk, but it is ten digits and dialable-looking, so the link builder accepts it. Rejecting numbers that look wrong would eventually reject a real one, and the operator finds out in one tap either way.
